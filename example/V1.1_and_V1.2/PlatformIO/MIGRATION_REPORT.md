# Migration Report

## Scope

Source was reviewed across `src`, `include`, image assets, PlatformIO configuration, and the original project dependency list. There are no project `CMakeLists.txt` files or custom PlatformIO Python scripts.

## Compatibility findings

The UI generated by SquareLine Studio is marked LVGL 9.1.0 and uses the LVGL 9 object/event/style APIs (`lv_obj_remove_flag`, `lv_obj_add_event_cb`, `lv_display_load_scr`-compatible generated helpers, and the LVGL 9 image descriptor). It therefore did not require a bulk UI rewrite.

The hand-written integration was the LVGL 8 compatibility boundary. The display and input driver registration structures were removed in LVGL 9, so `src/main.cpp` now creates opaque display/input objects and assigns callbacks through setters. Flush completion is explicitly delayed until LovyanGFX DMA completes.

## Risk disposition

- Compile/link risk: addressed by a clean PlatformIO build with pioarduino Espressif32 55.03.38, Arduino-ESP32 Core 3.3.8, LVGL 9.1.0, and LovyanGFX 1.2.25.
- Windows path risk: addressed by project-level `libdeps_dir` and `build_dir` settings that keep generated dependency and build paths out of the Chinese course directory.
- Display risk: ST7789 geometry, rotation, inversion, and RGB order remain inherited from the original LovyanGFX driver; verify on the panel.
- Touch risk: source contains a GT911 legacy header but the active LovyanGFX driver is FT5x06; verify the actual controller and calibration.
- Memory risk: partial internal DMA buffers replace two full-screen PSRAM buffers. This reduces allocation pressure but changes throughput characteristics.
- Flash/PSRAM risk: the course config overrides the generic DevKitC manifest with 16 MB flash, `huge_app.csv`, `qio_opi` memory type, and `BOARD_HAS_PSRAM`, matching the 2.4-inch course board settings.

## Validation

PlatformIO build completed successfully with no errors or link errors. No upload or runtime test was possible because no board was connected.

## API mapping and rationale

| LVGL 8.3 integration | LVGL 9.1 integration | Reason |
| --- | --- | --- |
| `lv_disp_draw_buf_t` | Buffers owned by `lv_display_t` | Display registration was redesigned in LVGL 9. |
| `lv_disp_drv_t` / `lv_disp_drv_register()` | `lv_display_create()` plus display setters | Driver structures are no longer initialized and registered by the application. |
| `lv_disp_flush_ready()` | `lv_display_flush_ready()` | The display API was renamed and consolidated. |
| `lv_indev_drv_t` / `lv_indev_drv_register()` | `lv_indev_create()` plus input setters | Input devices use the LVGL 9 object lifecycle. |
| External/implicit tick handling | `lv_tick_set_cb()` | The port now explicitly supplies the millisecond time source. |
| Two full-screen PSRAM buffers | Two 40-line internal DMA buffers | The selected board manifest reports no PSRAM; partial rendering avoids runtime allocation failure. |
